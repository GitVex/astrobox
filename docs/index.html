Astrobox.

The design system for the Trailblazers apps. Command Deck's construction lines and segmented bars carry the mechanics; brass, Noto Serif and dashed orbits carry the wonder. One package gives every app the same tokens, components, runtime, guidelines and agent rules.

01Overview

Astrobox is a set of rules first and a set of files second.

Every app built with it speaks one of two voices. The mechanical voice is for screens you operate, like the Datapad. The prose voice is for pages you read, like the Lore Lexicon. Frames say what they hold, dashed lines mean provisional, every number carries its unit, and secrets never reach the browser.

The element library shows every component live, with the palette editor, the type registers and the motion specimens. It loads the same package files your app does, so what you see there is what you get.

02What's inside

File
What it is
dist/astrobox.tokens.css
Every token as CSS variables: colour for night, day and both high-contrast modes, type, structure, motion and density per voice. Loads the three fonts.
dist/astrobox.css
All components, inside @layer astrobox, so your own unlayered styles always win.
dist/astrobox.js
The runtime: palette, orbits and moods, glyphs, units and tooltips, redaction, counting, motion, contents rail, brackets.
dist/astrobox.tokens.json
The same tokens in the W3C design-tokens format, for build tools.
nuxt.config.ts, plugins/
The Nuxt layer: stylesheets, fonts and the client plugin that initialises the runtime on every page.
GUIDELINES.md
The design guidelines for people.
AGENTS.md
The same rules for AI coding agents: hard rules, decision tables, snippets, API and checklist.
templates/
A Nuxt starter and a plain HTML example.

03New project

Pick the route that matches the app. All three load the same files; the Nuxt layer just does the wiring for you.

FastestStart from the templateA Nuxt app with Astrobox, a first screen and agent instructions. RecommendedAdd to a Nuxt appOne dependency, one line in the config. Anything elseVite, Vue, React or plain HTMLImport two stylesheets and one script.

Start from the template

npx giget gh:YOUR-USER/astrobox/templates/nuxt-starter my-app
cd my-app && npm install && npm run dev

The template extends the Astrobox layer, renders a mechanical Datapad screen with a counting hull meter, and ships a CLAUDE.md that points agents at the rules.

Add to a Nuxt app

  1. Install a tagged version: npm install github:YOUR-USER/astrobox#v1.0.0.
  2. Add the layer: extends: ['astrobox'] in nuxt.config.ts. This brings the tokens, the components, the fonts and the runtime plugin.
  3. Set the voice once per screen, on the outermost element: data-voice="mechanical" or data-voice="prose".
  4. Offer theme and contrast: set data-theme and data-contrast on <html>, or call $astrobox.setTheme() and $astrobox.setContrast().
  5. After rendering Astrobox markup outside a page change, call useNuxtApp().$astrobox.init(el).
Let Astrobox own its elementsRender units, meters, glyphs and redaction bars once, then update them through the runtime ($astrobox.count, setMood, init). If Vue re-renders their contents, the formatting is lost.

You can also skip the npm step and extend straight from GitHub: extends: ['github:YOUR-USER/astrobox#v1.0.0'].

Vite, Vue, React or plain HTML

// with a bundler, after npm install
import 'astrobox/tokens.css'
import 'astrobox/astrobox.css'
import 'astrobox/astrobox.js'   // initialises itself; call Astrobox.init(el) after renders
<!-- plain HTML, served from the tagged release via jsDelivr -->
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/YOUR-USER/astrobox@v1.0.0/dist/astrobox.tokens.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/gh/YOUR-USER/astrobox@v1.0.0/dist/astrobox.css">
<script src="https://cdn.jsdelivr.net/gh/YOUR-USER/astrobox@v1.0.0/dist/astrobox.js" defer></script>

jsDelivr only serves public repositories. For a private repo, copy dist/ into the app or install it with npm. templates/example.html is a complete page that uses nothing but the package.

04Retrofit an existing project

Move in under the old styles, then replace them screen by screen.

Because every Astrobox rule sits in a low-priority CSS layer, installing it changes almost nothing on day one: your existing styles keep winning until you delete them. That lets you migrate one screen at a time and ship in between.

Seven phasesShip after any phase
01

Audit

  • List the app's colours, fonts, spacing values and components.
  • Search for literal colours in component styles; each one needs a token.
  • List your custom properties that share a name with Astrobox's, such as --bg, --txt, --panel, --ln or --dim. Yours are unlayered, so they would override Astrobox's inside its components.
02

Install alongside

Add the package and the layer (or the two stylesheets and the script) exactly as for a new project. For each colliding custom property from the audit, either rename yours or point it at Astrobox's value, so both systems read the same colour.

03

Keep old components working by aliasing their tokens to Astrobox's. The Datapad's Command Deck tokens map almost one to one:

04

Set the voices

Put data-voice on each layout: mechanical for operating screens, prose for reading pages. This alone switches type, spacing, motion tempo and whether orbits show. Lore shown inside the Datapad becomes a prose inset; a stat block inside the Lexicon becomes a mechanical inset.

05

Replace components, leaves first

  • Start with labels, chips and buttons, then inputs and segmented controls.
  • Then frames and tables, following the frame vocabulary: cross-frame for systems, brackets for the featured object, orbit cards for entities.
  • Then numbers: every value becomes a <data class="u">, and tooltips only where they add information.
  • Then glyphs, on record references only.
  • Delete each old style as soon as nothing uses it.
06

Add the states and secure redaction

Give every data-backed component its empty, loading, error, stale and no-access treatment. For the Lexicon this is the important change: the server must send word lengths (data-words="7 6") instead of the withheld text, so nothing secret is ever in the page or the search index.

07

Verify and remove the bridge

  • Run Astrobox.auditFrames() and Astrobox.auditOrbits() on every screen.
  • Check night, day, high contrast and reduced motion.
  • Search for literal colours and durations; there should be none left.
  • Delete bridge.css.

05Updating

Apps pin a tag, so nothing changes under them until they choose to update. Versions follow semver:

  • Major (2.0.0): a class, attribute or token was renamed or removed. Read the changelog before updating.
  • Minor (1.1.0): new components or tokens. Safe to update.
  • Patch (1.0.1): fixed values or behaviour. Safe to update.

To update an app, change the tag in package.json and reinstall. Renovate or Dependabot can open these pull requests for you whenever a new tag appears.

06AI agents

Point your coding agent at the rules for the exact version the app uses. For Claude Code, add this to the app's CLAUDE.md:

For all UI work, follow node_modules/astrobox/AGENTS.md.
The full reasoning is in node_modules/astrobox/GUIDELINES.md.
Before finishing UI work, run Astrobox.auditFrames() and Astrobox.auditOrbits().

AGENTS.md holds the hard rules, the decision tables for frames, glyphs and images, markup snippets, the runtime API and a checklist to run before finishing.

08Changing Astrobox

  1. Edit files in src/. Never edit dist/ or docs/assets/; the build overwrites them.
  2. Run npm run build, then open docs/library/index.html to see the change in every component.
  3. Update GUIDELINES.md and AGENTS.md if a rule changed, and add a CHANGELOG.md entry.
  4. Bump the version in package.json, rebuild, commit, and tag: git tag v1.1.0 && git push --tags.

The check workflow rebuilds on every push and fails if the committed dist/ doesn't match src/. To publish these pages, enable GitHub Pages for the main branch and the /docs folder in the repository settings.
